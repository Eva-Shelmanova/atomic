# Исходные данные

## 1. NPPAD — временные ряды аварийных режимов АЭС

| Свойство | Значение |
|---|---|
| Полное название | NPPAD: An Open Time-series Dataset Covering Various Accidents for Nuclear Power Plants |
| Публикация | Qi B., Xiao X., Liang J. et al. An open time-series simulated dataset covering various accidents for nuclear power plants // Scientific Data. 2022. Vol. 9. Art. 766. doi:10.1038/s41597-022-01879-1 |
| Репозиторий | https://github.com/thu-inet/NuclearPowerPlantAccidentData |
| Использованная версия | коммит `a8d54ed0ed2c037bd39938d51f46c8f0df94b002` (25.08.2026) |
| Полная копия | Figshare, article 21299880 (~775 МБ) |
| Лицензия | MIT |
| Симулятор | PCTRAN, PWR, исходное состояние — 100 % мощности |
| Шаг записи | 10 с, пропусков нет |
| Параметров | 97 столбцов: TIME + 96 каналов (README, Table 2) |
| Классов | 18 (17 аварийных + нормальная эксплуатация) |
| Прогонов | 1217 |
| Строк (точек времени) | 492 709 |

### Состав репозитория и что используется

| Каталог | Содержимое | Использование |
|---|---|---|
| `NPPAD/<класс>/` | исходные базы PCTRAN (`N.mdb`, `Ndose.mdb`) и `NTransient Report.txt` | только Transient Report: тяжесть, номер неисправности (метки) |
| `Operation_csv_data/<класс>/N.csv` | 97 параметров во времени | основной источник |
| `Dose_csv_data/<класс>/Ndose.csv` | активности радионуклидов (I-131…Cm-244) | не используется (кандидат на скрытые каналы верификатора) |
| `Variable_Power_Data/` | 12 сценариев изменения мощности 1 %/мин, только .mdb | отложено до этапа C (D-003) |
| `Data Processing.py` | авторские скрипты: mdb→csv, сборка датасета, графики | изучен: авторы берут первые 150 точек (1500 с) прогона целиком как один пример |

Номер файла у классов с тяжестью означает тяжесть в процентах (README, Table 1): для течей — % от 100 см², для разрыва трубки ПГ — % от полного разрыва одной трубки, для стержней — % извлечения (RW) или введения (RI, отрицательные номера).

Аварийное воздействие во всех прогонах вводится в момент 0,5 с (`000000.5 sec, Malfunction # …` в Transient Report). Значит, время от начала прогона равно времени от начала аварии. Поэтому оно не передаётся генератору (D-008).

### Найденные особенности данных

- В 25 файлах SLBIC три лишних столбца (WPCS, WPMU, WPFW), отсутствующих в README. Отбрасываются (D-005).
- Порядок столбцов в CSV отличается от README (например, P идёт вторым). Загрузчик приводит столбцы к порядку реестра по имени.
- Семь каналов постоянны на всём train: QRHR, QFCL, EBK, MDBR, MCRT, MGAS, TCRT (в основном параметры тяжёлой аварии).
- 18 прогонов RI короче 120 с (минимум 110 с), из них не получается ни одного окна.
- В README у RI тяжесть указана как «% (+/−) insertion», в файлах — отрицательные значения −1…−100.

## 2. ETHZ Curated Nuclear Events Database — исторические события

| Свойство | Значение |
|---|---|
| Источник | ETH Zurich, Curated Nuclear Events Database (выпуск 17.11.2020) |
| Локальная копия | `ETHDB/ETHZ Curated Nuclear Events Database/` (архив и распакованные файлы) |
| Состав | `ETHZ_Database_Access_tool.xlsm` (база и инструмент доступа), `Support_file.xlsx`, руководство пользователя (.docx) |
| Сопутствующие статьи | `ETHDB/*.pdf`: описание базы, анализ 1250 событий-предвестников, оценка рисков, адаптивные модели ВАБ |
| Использование | подбор аналогов «в аналогичных случаях наблюдалось…» для верификатора гипотез (этап B2) |

Разбор структуры и подготовка `data/processed/ethz/events.json` описаны в [stage-B-methods.md](stage-B-methods.md).
