# Аудит данных NPPAD и ETHZ

Аудит выполнен на этапе C (25.10.2026) после того, как проверка отклонения от исходного состояния
показала «отклонений нет» для целых классов аварий. Результат повлиял на состав обучаемых классов (D-034).

## 1. Метод

Для каждого прогона NPPAD вычислено максимальное по времени и наблюдаемым каналам отличие
z-нормированной траектории от прогона ATWS, в котором неисправность введена с долей 0 % и
станция остаётся в стационарном состоянии. Сравнение — на общей длине двух прогонов.

## 4. Почему однопрогонные классы нельзя «размножить»

В NPPAD классы без параметра тяжести (ATWS, LACP, LOF, SP, TT, Normal — тип «Other» в таблице README)
смоделированы одним прогоном: у сценария нет числового параметра, который авторы варьировали.
Полная копия на Figshare (NPPAD.rar, 813 МБ, 2022) содержит те же исходные базы. Новые прогоны можно
получить только в симуляторе PCTRAN (коммерческий; скрипты автоматизации авторов лежат в
`Simulator Run Script/`), меняя, например, исходную мощность или момент ввода неисправности.
Без доступа к PCTRAN доступны:
- 12 прогонов изменения мощности (Variable_Power_Data, D-029) — внешний стресс-тест;
- использование однопрогонных классов как проб с ожидаемым исходом, а не как обучающих данных.
Аугментация (шум, сдвиги) одного прогона не даёт новых физических траекторий и не позволяет честно
оценить обобщение, поэтому не применялась.
